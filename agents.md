# AGENTS.md

## Проект

SeaNest — статический одностраничный сайт агентства недвижимости в Батуми, Грузия.

Основная цель сайта — получение заявки на персональный подбор недвижимости через форму, WhatsApp или Telegram.

Целевая аудитория — люди от 25 лет, покупающие недвижимость для жизни или инвестиций. Основные ценности проекта: прозрачность, юридическая безопасность, понятный процесс покупки и надёжное сопровождение.

## Язык и стиль общения

- Отвечай пользователю на русском языке.
- Комментарии в коде пиши на русском языке.
- Названия файлов, CSS-классов и JavaScript-переменных пиши на английском языке в нижнем регистре.
- Для составных имён файлов и классов используй kebab-case.
- Для JavaScript-переменных и функций используй camelCase.
- В конце работы кратко перечисляй выполненные изменения и затронутые файлы.
- Если задача допускает существенно разные реализации, сначала задай не более двух уточняющих вопросов.
- Не придумывай факты, цены, отзывы, контакты или характеристики объектов.

## Технологии

Используй только:

- HTML5;
- CSS3;
- чистый JavaScript;
- локальные изображения;
- SVG.

Не используй без отдельного согласования:

- React, Vue и другие фреймворки;
- TypeScript;
- Bootstrap, Tailwind и другие CSS-фреймворки;
- jQuery;
- npm и сборщики;
- сторонние библиотеки анимации;
- внешние сервисы аналитики;
- новые программы и зависимости.

Сайт должен запускаться как обычный статический проект без сборки.

## Структура проекта

Основная структура:

```text
index.html
privacy.html
css/
  style.css
js/
  main.js
images/
  logo.svg
  hero.webp
  properties/
```

Перед созданием новых файлов проверь, нет ли уже подходящих файлов и ресурсов.

Не удаляй и не переименовывай существующие файлы без явной необходимости и подтверждения пользователя.

## Источник данных

Достоверным источником информации о SeaNest считается:

https://ge-seanest.com/

С существующего сайта разрешено брать:

- название и логотип;
- контакты и ссылки на социальные сети;
- сведения об объектах;
- цены и характеристики объектов;
- информацию об услугах;
- подтверждённые показатели компании.

Перед использованием данных проверяй их актуальность.

Не копируй дизайн существующего сайта. Новый лендинг должен иметь самостоятельную визуальную концепцию.

## Контентные ограничения

Не добавляй:

- вымышленные отзывы;
- фотографии и персональные карточки сотрудников;
- неподтверждённые показатели;
- обещания гарантированной доходности;
- утверждение «90% клиентов приходят по рекомендации»;
- фиктивные награды и сертификаты;
- фиктивную отправку формы;
- тексты-заполнители Lorem ipsum.

Если достоверных данных не хватает, используй нейтральную формулировку или запроси их у пользователя.

## Структура лендинга

Основные разделы:

1. Закреплённая шапка.
2. Первый экран.
3. Преимущества.
4. Избранные объекты.
5. Этапы покупки.
6. Блок подтверждённых признаков надёжности.
7. Краткий блок о компании.
8. Форма заявки.
9. Контакты и подвал.

Главное целевое действие:

«Получить подборку объектов»

Дополнительные действия:

- написать в WhatsApp;
- написать в Telegram;
- запросить планировки выбранного объекта.

Не добавляй каталог, поиск, фильтры, блог, калькулятор доходности или личный кабинет без отдельного запроса.

## Дизайн

Стиль сайта — минималистичный, современный и спокойный.

Основная палитра:

```css
:root {
  --color-background: #081820;
  --color-surface: #102832;
  --color-text: #f1eee8;
  --color-text-muted: #9baeb5;
  --color-accent: #c8a96b;
  --color-accent-secondary: #3f8490;
}
```

Требования:

- не использовать белый фон;
- сохранять высокий контраст текста;
- использовать много свободного пространства;
- избегать визуального шума;
- не применять тяжёлые 3D-эффекты;
- не использовать фоновое видео;
- ограничиться одной стилистически цельной системой анимаций;
- использовать умеренные скругления и тонкие границы;
- не делать интерфейс похожим на шаблонный маркетплейс недвижимости.

## HTML

- Используй семантические элементы HTML5.
- На странице должен быть только один h1.
- Соблюдай логическую иерархию заголовков.
- Добавляй осмысленный alt всем содержательным изображениям.
- Для декоративных изображений используй пустой alt.
- Ссылки должны иметь понятный текст.
- Кнопки используй для действий, ссылки — для переходов.
- Не добавляй inline-стили и inline-обработчики событий.
- Подключай JavaScript с атрибутом defer.
- Добавляй SEO title, description и Open Graph metadata.

## CSS

- Используй CSS-переменные для цветов, размеров и отступов.
- Применяй mobile-first подход.
- Используй Flexbox и CSS Grid.
- Не применяй !important без крайней необходимости.
- Избегай чрезмерно специфичных селекторов.
- Не привязывай компоненты к случайной вложенности HTML.
- Проверяй отсутствие горизонтальной прокрутки.
- Добавляй видимые состояния hover, focus-visible и active.
- Учитывай prefers-reduced-motion.
- Не скрывай важный контент только ради визуального эффекта.

## JavaScript

- Используй чистый JavaScript без библиотек.
- Не загрязняй глобальную область видимости.
- Разделяй функциональность на небольшие функции.
- Проверяй существование DOM-элементов перед подключением обработчиков.
- Не используй JavaScript для того, что можно надёжно реализовать средствами HTML и CSS.
- Не сохраняй персональные данные пользователя в localStorage.
- Не выводи персональные данные в консоль.
- Не добавляй фиктивный ответ об успешной отправке заявки.

JavaScript может отвечать за:

- мобильное меню;
- изменение состояния шапки при прокрутке;
- плавную прокрутку;
- передачу названия объекта в форму;
- валидацию формы;
- формирование ссылки на WhatsApp;
- лёгкие анимации появления элементов.

## Форма заявки

Форма должна содержать:

- имя;
- телефон или контакт в мессенджере;
- необязательный бюджет;
- цель покупки;
- выбранный объект;
- согласие на обработку персональных данных.

Правила:

- используй понятные label;
- отмечай обязательные поля;
- показывай сообщения об ошибках рядом с соответствующими полями;
- не очищай форму при ошибке;
- не отправляй данные без явного действия пользователя;
- не имитируй серверную отправку;
- при отсутствии API разрешено сформировать сообщение и открыть WhatsApp;
- номер и ссылка WhatsApp должны храниться в одном явно обозначенном месте;
- перед реальным подключением API оставь понятный комментарий.

## Доступность

- Весь интерактивный интерфейс должен работать с клавиатуры.
- Используй видимый индикатор фокуса.
- Мобильное меню должно корректно сообщать своё состояние через aria-expanded.
- У интерактивных элементов должны быть доступные названия.
- Не используй один цвет как единственный способ передачи состояния.
- Поддерживай достаточный цветовой контраст.
- Не запускай навязчивую или бесконечную анимацию.
- Учитывай пользователей, отключивших анимацию.

## Адаптивность

Проверяй страницу как минимум на следующих ширинах:

- 360 px;
- 768 px;
- 1024 px;
- 1440 px.

На мобильных устройствах:

- навигация должна превращаться в доступное меню;
- карточки должны переходить в одну колонку;
- этапы покупки должны располагаться вертикально;
- кнопки и поля формы должны быть удобны для нажатия;
- текст не должен выходить за пределы экрана;
- декоративные элементы не должны перекрывать контент.

## Производительность

- Используй WebP или AVIF для растровых изображений.
- Не увеличивай маленькие изображения выше их исходного размера.
- Изображения ниже первого экрана загружай с loading="lazy".
- Для изображений указывай размеры или aspect-ratio.
- Не загружай тяжёлое видео.
- Не добавляй большие сторонние скрипты.
- Минимизируй количество запросов к внешним ресурсам.
- Не ухудшай читаемость ради высокого результата синтетических тестов.

## Безопасность

- Не изменяй, не удаляй и не переименовывай папку `backup`, её содержимое и файл `agents.md` без явного подтверждения пользователя. Не добавляй файлы в `backup` и не перезаписывай резервные копии без такого подтверждения.
- Не удаляй пользовательские файлы без явного подтверждения.
- Не устанавливай библиотеки и программы без объяснения и согласования.
- Не меняй системные настройки.
- Не размещай секретные ключи, пароли или токены в клиентском коде.
- Не передавай персональные данные в сторонние сервисы без согласования.
- Не добавляй внешние скрипты аналитики без запроса пользователя.
- Для внешних ссылок с target="_blank" используй rel="noopener noreferrer".

## Порядок работы

Перед изменениями:

1. Изучи структуру проекта.
2. Проверь существующие файлы и несохранённые изменения.
3. Составь короткий план.
4. Не меняй файлы, не относящиеся к задаче.

Во время реализации:

1. Делай изменения небольшими логическими этапами.
2. Сохраняй существующий рабочий функционал.
3. Повторно используй имеющиеся ресурсы.
4. Не оставляй неиспользуемый код.
5. Проверяй страницу после существенных изменений.

После реализации:

1. Проверь HTML, CSS и JavaScript на ошибки.
2. Проверь мобильную и десктопную версии.
3. Проверь меню, ссылки, форму и клавиатурную навигацию.
4. Проверь консоль браузера.
5. Кратко перечисли созданные и изменённые файлы.
6. Отдельно укажи, что требует ручного подключения или проверки.

## Критерии готовности

Задача считается выполненной, если:

- сайт запускается без сборки;
- отсутствуют JavaScript-ошибки;
- все разделы корректно отображаются;
- интерфейс адаптивен;
- мобильное меню работает;
- форма валидируется;
- выбранный объект передаётся в форму;
- контакты ведут на актуальные страницы SeaNest;
- нет вымышленных данных;
- отсутствует горизонтальная прокрутка;
- сайт доступен с клавиатуры;
- изменения перечислены в итоговом сообщении.
